<objective>
Harden `/api/agents/trigger` — the single chokepoint every one of the 13 automations flows through. Add: (1) cooldown dedup per (gym, agent, event, optional member, optional dedup_key), (2) `is_agent_initiated` + `dedup_key` in the payload schema (loop-safety contract Phase 6 consumes), (3) fire-and-forget forwarding to `UPTIMIZE_WEBHOOK_URL` with failure recording, (4) a documented PLATFORM_EVENTS tier-gating bypass.

Purpose: Pitfall 7 / roadmap constraint — dedup MUST land before ANY new trigger call site (all Wave 2 plans depend on this plan). Forwarding turns log-only triggers into verified calls arriving at the (staged) UptimizeAI engine (AGENT-01).

PLATFORM_EVENTS design decision (planner-resolved, surfaced for human review at the 05-07 gate): `upgrade-opportunity` (revenue-agent, Pro-only) fires precisely BECAUSE a gym lacks a tier, and `new-gym-onboarded` (growth-agent, Pro-only) fires for brand-new gyms that are always 'starter' at registration. Under strict tier gating both automations would be dead code — permanently skipped. Resolution: `PLATFORM_EVENTS = ['new-gym-onboarded', 'upgrade-opportunity']` bypass `checkAgentAccess` because they are platform-growth events ABOUT the gym, not agent services delivered TO the gym's members. All other events remain strictly tier-gated (AGENT-05: starter = 0 gym-scoped fires).

Output: hardened trigger route + pure cooldown module + comprehensive test file (TDD RED-first).
</objective>
