Cron auth pattern (copy from agent-daily — dual header):
```typescript
const providedKey =
  request.headers.get('x-smartgym-internal-key') ??
  request.headers.get('authorization')?.replace('Bearer ', '') ?? null;
// valid when === process.env.SMARTGYM_INTERNAL_KEY or === process.env.SUPABASE_SERVICE_ROLE_KEY
```

Expo receipts API: POST https://exp.host/--/api/v2/push/getReceipts, body `{ ids: string[] }` (max 100/call). Response: `{ data: { [receiptId]: { status: 'ok' } | { status: 'error', message: string, details?: { error?: 'DeviceNotRegistered' | ... } } } }`. Receipt IDs absent from the response are still pending — leave those rows untouched.

notification_log (after migration 031): status IN ('sent','failed','delivered'); expo_receipt_id text; profile_id (auth users.id). device_tokens: profile_id, expo_push_token, active.
</interfaces>

RED first, then implement POST /api/cron/receipt-poll:

2. Query notification_log: status='sent' AND expo_receipt_id IS NOT NULL AND created_at > now-24h AND created_at &lt; now-30min (Expo says poll after ~15-30 min; the 30-min floor avoids polling too-fresh tickets), order created_at ASC, limit 100.
