**complete_gym_onboarding RPC** (from plan 01-01): `admin.rpc('complete_gym_onboarding', { p_user_id, p_gym_name, p_gym_slug, p_gym_city, p_gym_type, p_tier })` returns the new gym uuid. Handles slug collisions internally.

**Email flow (CRITICAL — differs from research doc):** `admin.auth.admin.createUser({ email_confirm: false })` does NOT send a confirmation email. Then use the service-role admin client for the `users` insert + RPC. On RPC/insert failure: `admin.auth.admin.deleteUser(userId)` to prevent orphaned auth users. Duplicate email: signUp returns an obfuscated fake user with `identities: []` — detect via `data.user?.identities?.length === 0` and return 409 "An account with this email already exists".

```typescript
export const onboardRegisterSchema = z.object({
  owner_name: z.string().min(2).max(100).trim(),
  email: z.string().email().max(255),
  password: z.string().min(8).max(72),
  gym_name: z.string().min(2).max(100).trim(),
  city: z.string().max(100).trim().optional(),
  gym_type: z.enum(['independent','crossfit','martial-arts','yoga','personal-training','corporate','other']).optional().default('independent'),
```

**`api/onboard/register/route.ts`** POST:
1. `checkRateLimit('onboard-register:' + (request.headers.get('x-forwarded-for') ?? 'local'), 5, 600_000)`
2. Validate body (400 on failure)
3. Anon server client `signUp({ email, password, options: { emailRedirectTo: `${appUrl}/subscribe`, data: { display_name: owner_name } } })` — `appUrl` from `process.env.NEXT_PUBLIC_APP_URL || 'http://localhost:3000'`
4. Handle: signUp error → 500 (log server-side, generic client message); `identities.length === 0` → 409 duplicate
5. Admin client: insert `users` row `{ id: userId, email, display_name: owner_name, platform_role: 'gym_owner' }`
6. `admin.rpc('complete_gym_onboarding', { p_user_id: userId, p_gym_name: gym_name, p_gym_slug: generateSlug(gym_name), p_gym_city: city ?? null, p_gym_type: gym_type, p_tier: 'starter' })`
7. Steps 5-6 failure → `await admin.auth.admin.deleteUser(userId)` (best-effort try/catch around the delete too), return 500
8. Return `{ gym_id, email }`

**`api/onboard/status/route.ts`** GET (session-based, NOT verifyStaff — the wizard user is an owner but this route also reports pre-checkout state):
1. `createServerSupabaseClient()` → `auth.getSession()`; no session → 401
2. Query `gym_memberships` (role owner, status active) for the user → no membership → 404 `{ error: 'no_gym' }`
3. Admin client: fetch `gyms.name, subscription_tier` + `gym_billing.stripe_customer_id, stripe_subscription_id, subscription_status`
4. Return `{ gym_id, gym_name, tier, email_confirmed: !!session.user.email_confirmed_at, billing: { has_customer: !!stripe_customer_id, has_subscription: !!stripe_subscription_id, subscription_status } }`
